## Project

Composite GitHub Action that auto-syncs Credly certifications/badges into a profile README between `<!-- CREDLY-BADGES:START/END -->` markers. The `output` input picks the mode: `readme` (the default, the original behavior), `svg` (one self-contained animated SVG card of every badge, written to `svg-path`, plus a 340px phone card at `svg-mobile-path` when that is set), or `both`. `hide-expired`, `sort` and `max-badges` pick the badges; `commit: true` makes the action commit and push what it wrote.

Published as `Sagargupta16/credly-badge-readme-action@v1`; runs live on Sagar's profile README via weekly cron.

## Stack

- **Language**: Python 3.13, stdlib only; Pillow is optional and only SVG mode uses it
- **Framework**: GitHub Actions composite action (`action.yml`)
- **Database**: none
- **Package manager**: none; `action.yml` pip-installs a pinned `pillow==13.0.0` wheel only when `output` is not `readme`
- **Deploy target**: consumed via `uses:` in other repos' workflows; releases are git tags

## Run

```
CREDLY_USERNAME=<credly-username> python update-credly-badges.py
```

Needs a `README.md` with the CREDLY-BADGES markers in cwd (or set `README_PATH`). SVG mode needs no README; with Pillow it renders exactly like the action:

```
CREDLY_USERNAME=<credly-username> OUTPUT=svg SVG_PATH=/tmp/card.svg uv run --no-project --with pillow==13.0.0 python update-credly-badges.py
```

`examples/credly-badges.svg` and `examples/credly-badges-mobile.svg` (the README's top image, desktop and phone) were rendered that way from `sagar-gupta.f8eb96cc` with `SVG_MOBILE_PATH=examples/credly-badges-mobile.svg`; rerun it to refresh them. `scripts/phone-preview.py` (Playwright plus Pillow, needs the network) then re-measures GitHub's README width on a 375px phone, prints each card's scale and label size, and rewrites `docs/phone-preview.webp`; the README's phone-card numbers come from its output, so rerun it when either card's layout changes.

The How It Works diagram, `docs/diagrams/how-it-works-dark.svg` and `-light.svg`, is generated by orrery from `docs/diagrams/how-it-works.yaml`; edit the spec, never the SVGs, and re-render with the command in its header. Every node carries `evidence:` (a file, line and identifier in this repo), so when the script, `action.yml` or the README workflow examples move, `orrery verify docs/diagrams/how-it-works.yaml` says which nodes to update.

## Test

```
uv run --with pytest python -m pytest -v
uv run --with pytest --with pillow==13.0.0 python -m pytest -v
uv run --with ruff ruff check .
```

`test_update_credly_badges.py` covers the pure functions (categorization, HTML escaping, marker splicing, empty-category skipping), fetching (following a second page, stopping on a 404 without a retry), the SVG card (grouping, per-row wrapping, dash normalization, escaping, XML validity), the image path (WebP at twice the drawn size with transparent corners, same bytes twice, the PNG fallbacks with no Pillow and with a Pillow lacking WebP), badge selection (`hide-expired`, `sort`, `max-badges`), the phone layout and its image sharing, and `main()` in each mode, with every fetch stubbed. The `commit: true` tests run real `git` against a bare remote in `tmp_path`. The five Pillow tests skip where Pillow is not installed, which includes CI's `test` job; run the second command above before touching `downscale()`. `FROZEN_SECTION` there is README mode's output captured before SVG mode existed (main at 92ca53e): if that test fails, README mode changed for every consumer. `.github/workflows/ci.yml` has three jobs, on every push to `main` and every PR: `lint` (ruff, Python 3.13 only), `test` (pytest, matrixed over 3.12/3.13/3.14 -- 3.13 is the version `action.yml` installs for consumers), and `action`, which is the only job that loads `action.yml`: it runs the composite action from the checkout against a scratch README and fails if any of the five outputs comes back empty or if a step gated on `changed` gets skipped, then runs it again with `output: svg` and `svg-mobile-path` and fails unless both cards parse as XML at 840px and 340px with every badge image inlined as WebP. Nothing in CI runs `commit: true` (it would push to this repo); the tests cover it. That second run is the only place the Pillow install step and the live badge-image fetch execute, so it is also CI's only check of the WebP path.

`ruff==0.17.1` and `pytest==9.1.1` are pinned inline in `ci.yml`, and `pillow==13.0.0` in `action.yml`, so a tool release cannot turn an unchanged tree red: ruff 0.16.0 grew its default ruleset from 59 rules to 413, which flagged `I001` on an unchanged import block here. Bump them by hand; Renovate's github-actions manager reads `uses:`/`with:`/`container:`/`services:`/`runs-on:`, not `run:` text. A `requirements-dev.txt` does not work here either: SonarCloud rule `githubactions:S8544` fails the quality gate when the installed versions are not visible at the `pip install` site (measured on PR #8).

There is deliberately no `ruff.toml`: an earlier one cut enforcement from ruff's 413 default rules to 100, and the tree passes the full default set anyway. That narrowing hid a real finding, `EXE001` on the script's shebang, which is why `update-credly-badges.py` is mode 100755 in git.

For an end-to-end check by hand, run the script standalone against a scratch README containing the markers, then eyeball the generated HTML.

## Key files

- `action.yml` -- env var names here must match the `os.environ` reads in the script

## Gotchas

- Adding an input means touching three places in sync: `action.yml` inputs, `action.yml` env block, and the env read in the script.
- `v1` is a moving major tag. After cutting a new `v1.x.y`, retag: `git tag -f v1 && git push -f origin v1`, and update `CHANGELOG.md`.
- Every release since v1.1.0 has moved `v1` (v1.2.0 on 2026-10-11, commit `558f618`; v1.4.0 on 2026-10-25, commit `4026ed5`, which also shipped 1.2.1 to 1.3.2, never tagged); `git ls-remote --tags origin 'v1^{}'` shows where it points now.
- Moving the `v1` tag does not reach Sagar's own profile. `Sagargupta16/Sagargupta16/.github/workflows/update-credly-badges.yml` pins a full commit SHA with a `# vX.Y.Z` comment, so a release means three steps: tag `v1.x.y` on the merge commit, move `v1`, then re-pin that workflow to the new SHA.
- Moving `v1` does reach other people. A GitHub code search on 2026-10-18 found 3 public workflows on `Sagargupta16/credly-badge-readme-action@v1`: `Unknown27s/Unknown27s` (`.github/workflows/update-badges.yml`), `khaizr0/khaizr0` and `wogho/wogho` (`update-credly-badges.yml`). All three run README mode (no `output:` input) and commit on `git diff`, so any change to README mode's bytes lands as a commit in their repos on their next run, which is what `FROZEN_SECTION` guards. A Pillow bump does not reach them: README mode never installs it.
- Composite action outputs need an explicit `value:` mapping plus an `id:` on the step that writes `$GITHUB_OUTPUT`. Declaring only a `description` makes every output silently resolve to an empty string.
- Badge names/URLs from the Credly API are `html.escape()`d before interpolation -- untrusted data, keep it.
- `update_readme` uses `re.subn` with a lambda replacement so backslashes in badge content are literal, not backreferences. Don't "simplify" it away.
- `MAX_RETRIES <= 0` is intentionally clamped to 1 attempt in `fetch_url`. A 4xx other than 429 is raised on the first attempt (retrying cannot fix it), and `fetch_badges` turns a 404 into a `fail()` that names the username.
- Data source is the undocumented public endpoint `https://www.credly.com/users/{username}/badges.json` (`{"data": [...], "metadata": {...}}` shape). If it breaks, that endpoint changed. It is paginated at 48 badges (`metadata.per`; a `per=` query is ignored, probed 2026-10-18), and `fetch_badges` follows `metadata.next_page_url`, only under `https://www.credly.com/users/` (`CREDLY_USERS`), and returns the joined `{"data": [...]}`.
- The SVG card design came from `brand/Sagargupta16/scripts/render-svgs.py` (`render_certs`, 2026-09-25). The profile has since dropped its copy and writes `assets/svg/certs.svg` with this action (pinned by SHA in its `update-credly-badges.yml`), so a card change reaches the profile only when that pin moves.
- Label floor: 10.5 px on the 840 px card since 1.4.0, with four label lines under certifications and three under the rest. `label_font` still shrinks a single word that is wider than its column (`WELL-ARCHITECTED` at 8.2 px on the example). Check a size change against the example's 22 badges for dropped words: `label[:lines]` drops a label's extra lines without a warning.
- The card fetches each badge's original `image_url`, not a `size/NxN` URL: the Credly CDN serves a resized image only for some sizes, differently per badge, and 302s every other size to the original (measured 2026-09-25: sizes 110, 160, 220 and 340 across all 22 badges of the profile above). Pillow then shrinks each image to twice its drawn size (84 and 58 px drawn) and re-encodes it as WebP, `quality=85, method=6`, whose alpha channel stays lossless: 124,099 bytes for those 22 badges with `pillow==13.0.0` (measured 2026-10-18; 124,291 with 12.3.0), against 390,601 as optimized PNG (v1.1.x) and 1,256,889 without Pillow (re-measured 2026-10-18). A Pillow without libwebp (`features.check("webp")` false) falls back to the optimized PNG. The card is still over svg-forge's 100 KiB README budget (124,099 bytes is 121.2 KiB): the 22 base64 WebP images alone are 111,856 bytes, so the size grows with the badge count and no quality setting keeps every profile under it.
- Badge images are fetched only from `https://images.credly.com/` (`badge_data_uri` refuses anything else), since the URLs come from the API. Keep the check: urllib would also open a `file://` URL.
- The Pillow install in `action.yml` must stay a YAML block scalar (`run: |`): a bare `:all:` in a plain scalar parses as a mapping. Renovate does not read the pin there; bump it by hand.
- SVG output is deterministic for a given Pillow version, which is what makes `git diff` a valid change check for consumers. Anything time- or order-dependent in `render_svg` would break that. The WebP card is byte-identical across runs and across the Windows and Linux wheels: checked for `pillow==12.3.0` on 2026-10-11 and for `pillow==13.0.0` on 2026-10-18 (Windows cp313 against the manylinux cp312 wheel under WSL Ubuntu, 124,099 bytes both, libwebp 1.6.0). A Pillow version bump is not byte-stable even with the same libwebp: 12.3.0 and 13.0.0 render different bytes, so every bump means one card commit for each consumer. The old PNG path was not stable across platforms either: its pixels matched but the bytes differed between the 12.3.0 wheels.

## Repo-specific rules

- Keep README mode stdlib-only. The one third-party import is Pillow, inside `downscale()` behind `except ImportError`, and `action.yml` installs it only when `output` is not `readme`; any other third-party import silently breaks every consumer.

## Usage

- In a workflow: `uses: Sagargupta16/credly-badge-readme-action@v1` with `credly-username` input; consumer workflow commits the README change itself (see README examples), or sets `commit: true`. Add `output: svg` (or `both`) for the card; the README's SVG example commits it on `git diff`.
- Standalone: `CREDLY_USERNAME=<u> python update-credly-badges.py` (add `OUTPUT=svg` for the card).

## Config

- No config file. Everything flows action input -> env var -> script: `CREDLY_USERNAME` (required), `README_PATH`, `BADGE_SIZE`, `MAX_RETRIES`, `CERT_KEYWORDS`, `PROFESSIONAL_KEYWORDS`, `OUTPUT`, `SVG_PATH`, `SVG_GROUPS`, `SVG_PER_ROW`, `SVG_MOBILE_PATH`, `ACCENT`, `HIDE_EXPIRED`, `SORT`, `MAX_BADGES`, `COMMIT`, `COMMIT_MESSAGE`.
- `hide-expired`, `sort` and `max-badges` run in `select_badges` before categorization, and every input except the SVG ones is validated before the first fetch, in every mode. Their defaults (`false`, `credly`, `0`) return the API list untouched, which keeps README mode on `FROZEN_SECTION` and the example card byte-identical (checked 2026-10-18 against a 1.2.1 render). `total-badges` counts the badges after selection.
- The phone card is `render_svg(..., MOBILE)` with `MOBILE_PER_ROW` (3, 4), 340px wide. Its badge sizes (84 and 58) match the 840px card's defaults on purpose: `main()` passes one `images` dict to both renders, so with default `svg-per-row` the second card fetches nothing. `line_step()` keeps the 840px card's 12px label spacing and only grows for the phone card's larger fonts.
- `commit: true` runs `git add`, `git commit -- <paths>` and `git push` in the working directory as `github-actions[bot]`, only when `changed` is true and only for the files the run wrote, so other changes in the checkout stay out of the commit.
- Categorization is keyword-substring match against `badge_template.name`; cert keywords win over professional, remainder is knowledge. The SVG card reuses it: `svg-groups: two` merges professional and knowledge into one "Learning and partner badges" group, `three` keeps all three.
- SVG inputs are validated only when `output` is not `readme`, before any network call: `svg-groups` two or three, `svg-per-row` whole numbers 1 to 12 (`MAX_PER_ROW`), `accent` a 3- or 6-digit hex color with or without `#`.
